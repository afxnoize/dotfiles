# mermaid ガイド

描画の確認は、人が目視で行う。ここでは、書く前に避けるアンチパターンだけを定める。

## 図を入れる基準

- 構造、流れ、依存関係を説明するときだけ入れる。箇条書きで足りるなら、図にしない。
- 1 文書に 2 つまで。1 つの図は、ノード 10 個まで。どちらも初期値。
- 図の直前に 1 文で、その図が何を示すかを書く。

## ラベルのアンチパターン

- 長い日本語ラベルを、改行なしで書かない。語の切れ目に `<br/>` を入れる。
  - 良い例：`A["入力の確認<br/>出力パスが無ければ<br/>止まる"]`
- 1 行を全角 12 字より長くしない。英数字を含む行は、全角換算で 10 字までにする。幅の上限を超えると、語の途中で割れる。
- 1 つのラベルを 4 行以上にしない。詳細は本文に回す。
- 辺のラベルを長くしない。全角 6 字までにする。
- 特殊文字（`( ) [ ] { } : / | #` と引用符）を含むラベルは、`"…"` で囲む。
- `end` を小文字のまま、ノードの文字列に単独で使わない。
- ノード ID に日本語を使わない。短い英数字にする。

## 構造のアンチパターン

- `subgraph` を使わない。タイトルが中のノードと重なって読めなくなったことがある。
- 色（`classDef`、`style`）を多用しない。使うなら、`fill` と `color` を必ず対で指定する。ダークテーマで文字が消える報告がある。
- 方向は `TB` を基本にする。`LR` は、ラベルが長いと横に伸びて、表示先で縮小される。

## 渡し方

- 図は未描画のまま渡す。最終報告に「図は未描画。見切れの目視確認が必要」と書き、図の位置を列挙する。
- 見切れが出たら、そのラベルを短くするか、`<br/>` を足す。

## 数値の根拠

- 12 字と `subgraph` は、mermaid 11.12.0、Noto Sans CJK JP、`htmlLabels: false` の環境で、1 回ずつ実測した値。表示先の描画エンジンでは変わりうる。見切れが実際に出たら、数値を直す。
- `end` の規則は mermaid の公式ドキュメントにある。ダークテーマの報告は GitHub の issue による。この環境では再現していない。
